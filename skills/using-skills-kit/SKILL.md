# Дисциплина навыков skills-kit

Каталог навыков в системном промпте — не справочник, который листают при желании, а обязательный шаг перед работой. Навык, загруженный после того, как решение уже принято, бесполезен: он объясняет, как делать, а не оправдывает сделанное.

## Когда открывать

- Задача ещё не тронута: разведка, чтение файлов и уточняющий вопрос впереди — навык нужен до первого действия, а не после решения.
- «Какие навыки есть?», «проверь навыки», «почему не использовал навык», «что открыть под эту задачу» — разговор о дисциплине, а не о предмете работы.
- **Симптом:** правки уже идут, а навык вспомнился задним числом; объявления «Использую … для …» не было вовсе; подходящий навык нашёлся после решения.
- Не открывать, если под задачу уже есть более точный навык — сразу открывать его; за правкой самой библиотеки — `skill-library-maintenance`; за поиском готового навыка — `skill-sourcing`.

## Правило

1. **Перед любым ответом или действием** — включая уточняющий вопрос, чтение файлов и разведку — проверить, есть ли навык под эту задачу.
2. **Есть хотя бы 1% шанс, что навык применим — загрузить его** (инструментом загрузки навыков хоста, с точным именем) до ответа. Не подошёл — не использовать.
3. **Тип действия сменился — каталог проверяется заново.** Просьба задаёт только первое действие. Как только в работе появляется действие другого класса — клонирую репозиторий, собираю образ, поднимаю контейнер, пишу вне проекта — это новая задача со своим навыком (`local-work-hygiene`, `secrets-hygiene`), и проверка идёт до первого такого действия, а не после первого упавшего вызова.
4. **Объявить:** «Использую `<навык>` для `<цели>`».
5. **Если у навыка чек-лист** — завести todo по пунктам и идти по нему.
6. **После работы** — проверить, не надо ли обновить навык (`skill-library-maintenance`): урок, который не записан, потерян.

## Приоритет

Процессные навыки идут первыми — они задают подход, предметные выполняют:

| Ситуация | Первый навык |
|---|---|
| «Давай сделаем X», цель не ясна | `brainstorming` |
| Задача больше одного шага | `plan` |
| Есть утверждённый план | `subagent-driven-development` |
| «Готово / проходит / исправлено» | `verification-before-completion` |
| Перед коммитом или PR | `requesting-code-review` |
| Пуш, тег, релиз | `github-pr-workflow` |
| Баг непонятен | `systematic-debugging` |
| Пишется логика | `test-driven-development` |
| Задача делится на куски | `delegating-to-subagents` |
| Нужен готовый навык или промпт | `skill-sourcing` |

## Красные флаги: это рационализация

| Мысль | Реальность |
|---|---|
| «Это простой вопрос» | Вопрос — тоже задача. Проверь навык. |
| «Сначала соберу контекст» | Навык говорит, как собирать контекст. |
| «Я помню этот навык» | Навыки меняются. Читай текущую версию. |
| «Тут не нужен формальный подход» | Если навык есть — он и есть подход. |
| «Уже поздно, я в середине» | Проверь сейчас, до следующего шага. |
| «Это побочное действие, а не задача» | Побочное действие создаёт файлы и меняет состояние машины. Навык под него открывается до первого такого действия. |
| «Навык не подойдёт» | Загрузи и убедись, а не решай по названию. |

## Где каталог

- В системном промпте — список навыков с триггерами.
- Полный каталог с уровнями и «когда открывать» — `INDEX.md` в репозитории `skills-kit`.
- Ничего не нашлось — `skill-sourcing` (поиск готового) или `skill-library-maintenance` (создать свой).

## Проектная папка `.agents`

Если в рабочем каталоге проекта есть `.agents/` — это память проекта, и она читается раньше кода: `README.md` → `context/project.md` → `context/process.md` → `context/team.md` → `context/state.md`. Папки нет — не ошибка, продолжай без неё.

Что в ней лежит, что коммитится, что хост находит сам и как поймать теню проектного навыка — `references/agents-layout.md`.

## Стоимость

1% — порог для **проверки**, не для загрузки. Под задачу открываются один-два навыка, а не весь каталог: двадцать навыков в контексте — шум, в котором теряются детали.

## Исключение: субагент

Если ты запущен с конкретным брифом (делегированная задача) — не ищи навыки заново: следуй брифу и правилам родителя. Дисциплина относится к главной сессии; ребёнку навыки подменяют задание.

## Как это попадает в первую сессию

Навык сам себя не загрузит, поэтому правило дублируется в стартовую инструкцию хоста — файл, который читается в начале каждой сессии. Какой это файл, где он лежит и какой у него бюджет, — в документации своего хоста; готовый блок для вставки — `references/agents-md-bootstrap.md`.

Блок в стартовой инструкции — сокращённая копия раздела «Правило» этого навыка. При правке синхронизировать оба места, иначе копии разойдутся.

## Файлы

- `references/agents-md-bootstrap.md` — короткий блок для вставки в стартовую инструкцию хоста (какой именно файл — по документации своего хоста).
- `references/agents-layout.md` — карта `.agents/`: что читать, что коммитится, что хост находит сам.
