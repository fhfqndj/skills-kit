# `.agents`: рабочая папка проекта

`.agents/` — одна папка в корне проекта, где живёт всё, что агент читает и пишет
про этот проект: память, планы, проектные навыки, правила и отчёты ревью. Её
читает любой harness, а не только текущий, поэтому личные пути и имена
инструментов сюда не попадают.

## Карта

```text
<project>/.agents/
├── README.md          карта папки: что здесь есть и что коммитится — читается первым
├── context/           память проекта: project.md, process.md, team.md, state.md
├── plans/             планы: YYYY-MM-DD_HHMMSS-<slug>.md
├── skills/            проектные навыки: <name>/SKILL.md
├── review-rules/      политика ревью: плоские *.md или папки по областям (backend/, frontend/)
├── review-reports/    отчёты прогонов ревью: YYYY-MM-DD-<slug>.md
└── plugins/           манифест для агент-хаба, если проект ставится как плагин
```

В корне — только `README.md` и папки. Контекстные документы в корень не
кладутся: иначе папка превращается в свалку и непонятно, что читать первым.

## Что коммитится

Папка гибридная: контракт коммитится, черновик — нет.

| Путь | В git | Почему |
|---|---|---|
| `README.md`, `skills/`, `review-rules/`, `plugins/` | да | это контракт: его видят вторая сессия, коллега и ревьюер |
| `context/`, `plans/`, `review-reports/` | нет | снимок и черновики: шумят в diff и устаревают за день |

Игнор — по подпапкам, а не всей папкой:

```bash
printf '.agents/context/\n.agents/plans/\n.agents/review-reports/\n' >> .gitignore
```

В чужом форке дешевле локальный исключающий файл репозитория (`.git/info/exclude`):
он не попадает в чужой репозиторий и не спорит с его `.gitignore`.

**Правило коммита записывается в `.agents/README.md`**, иначе следующая сессия
закоммитит `context/state.md` или черновик плана.

## Что хост находит сам

Хосты ищут навыки в нескольких корнях: проектные, пользовательские и
harness-специфичные. Правила общие для всех:

- **Проектный корень бьёт пользовательский.** Проектный навык — часть контракта
  проекта, личная библиотека — общий запас.
- **Harness-специфичный корень бьёт переносимый.** Специфику конкретного
  инструмента кладут в его собственный корень, всё переносимое — в
  `.agents/skills`.
- **Тень молчит.** Копия универсального навыка в проекте перекрывает его
  навсегда и без предупреждения: правка в библиотеке перестаёт доходить.

Точные имена корней, порядок и приоритет — по документации своего хоста.

Проверка на тень — пересечение имён проектных навыков с пользовательской
библиотекой:

```bash
comm -12 <(ls .agents/skills 2>/dev/null | sort) <(ls <host-skills-dir> | sort)
```

Пусто — хорошо. Имена в выводе — либо осознанный override с записанной в
`README.md` причиной, либо дубль, который удаляют.

## Завести в новом проекте

```bash
mkdir -p .agents/{context,plans,skills,review-rules,review-reports}
printf '.agents/context/\n.agents/plans/\n.agents/review-reports/\n' >> .gitignore
```

Дальше — `README.md` с картой: что здесь есть, что коммитится, какой файл читать
первым. Без него папка через месяц читается как мусор.

## Проверка

- `ls .agents` — в корне только `README.md` и папки.
- `git status --short .agents` — в индексе нет `context/`, `plans/`,
  `review-reports/`.
- Пересечение имён проектных и глобальных навыков пусто или объяснено.
