# Как предложить изменение

Репозиторий — публичный набор навыков для AI-агентов: `skills/<навык>/SKILL.md`
плюс, при необходимости, `references/`, `templates/`, `scripts/`. Правила формата
и критерии отбора — в [README.md](README.md); инструкции агенту — в
[AGENTS.md](AGENTS.md).

## Что принимается

- Универсальная процедура: работает в разных проектах и harness, не зависит от
  одного инструмента, аккаунта или машины.
- Проверенная практика: есть след применения — прогон, замер, разбор, — а не
  «на будущее».
- Операциональное правило: команда проверки, порог или критерий выхода рядом
  с правилом.

Не принимаются: пересказ общих знаний модели, личные имена и пути, проектные
примеры, секреты, привязка к конкретному рантайму.

## Перед PR

```bash
make check    # check.py + lang_check.py + check_examples.py
make test     # валидатор, установщик, упаковка, поиск, routing-эвалы
python3 scripts/routing_eval.py --min-rank1 100
```

Требования, которые проверяются автоматически:

- frontmatter: `name` = имя каталога, `description` ≤60 символов и начинается
  с триггера, `version`, `author: fhfqndj`, `license: MIT`, `platforms`,
  `metadata.group`, `metadata.tags`; `related_skills` — только на навыки
  этого репозитория;
- `SKILL.md` ≤250 строк; длинные разборы — в `references/` навыка;
- один язык на навык; код, команды и пути не переводятся;
- плоская раскладка `skills/<навык>/`; вложенный `SKILL.md` ломает установку;
- в тексте нет абсолютных домашних путей, секретов и имён людей.

Новый навык без строки в `INDEX.md` не существует: добавьте строку с уровнем
(L1/L2), триггером и числом файлов.

## Коммиты и PR

- Сообщение — `type: описание`, тип из `git-naming` (`feat`, `fix`, `docs`,
  `test`, `refactor`, `build`, `chore`, `ci`), до 6 слов, нижний регистр.
- Один PR — одна тема; механические правки (переименования, форматирование)
  отдельным PR.
- В описании PR: что изменено, чем проверено (команда и её вывод), что
  сознательно не трогали.

## Релиз

Релиз делает мейнтейнер: версия поднимается в пяти манифестах, добавляется
запись в [CHANGELOG.md](CHANGELOG.md), ставится тег `v<версия>` — workflow
соберёт zip и опубликует ассет. Definition of Done — в
[AGENTS.md](AGENTS.md#definition-of-done-релиза).
