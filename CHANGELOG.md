# Изменения

Формат — по мотивам Keep a Changelog; версия в `plugin.json`, тег — `v<версия>`.

## 1.2.0 — 2026-11-19

Навыки связаны друг с другом контрактом, а не догадкой; из текстов убрано то, что верно только для одного хоста.

### Добавлено

- `plan` печатает `Spec`, `Global Constraints`, `Repository` и `Interfaces: Consumes / Produces`;
  секция `## Tasks` с `- [ ] Task N` — очередь исполнителя.
- `subagent-driven-development` читает реестр из файла плана (переживает компакцию), отмечает
  `[x]` после второй приёмки, возвращает план без `Interfaces` автору.
- `systematic-debugging`: выход «причина внешняя» — только после доказательства, что локальная
  обработка корректна; сдерживание делается по TDD, с регрессионным тестом.

### Исправлено

- `test-driven-development`: GREEN больше не разрешает остановиться на захардкоженном значении;
  гейт — второй тест с другим входом; граничный случай закрывается RED/GREEN, а не REFACTOR.
- Счёт попыток фикса сведён к одному правилу: две попытки на гипотезу, третья — с новой,
  четыре и больше — вопрос архитектуры.
- Убрана привязка к рантайму: лимит «8 членов», текст ошибки хоста, имена инструментов, TCC,
  `origin/master`; числа без проверки (95%/40%, 2000/5000 строк) заменены проверяемыми
  формулировками; в `quality-bar` каждое число получило падающую команду.
- Дубли сведены **внутри** навыков; правило «между навыками ссылка запрещена» записано в README
  и AGENTS: навык устанавливается отдельно и обязан работать без соседа.

## 1.1.1 — 2026-11-19

Починка примеров и гейтов: команды из навыков должны запускаться, а проверки — не врать.

### Исправлено

- Примеры стали переносимыми: `python` → `python3` (26 мест), `timeout` → `perl -e 'alarm …'`,
  BSD-`sed -i ''` → `perl -pi -e`, `assert` в bash → `[ … ] || exit 1`, `***` вместо токена →
  переменная, `git filter-branch` → `git filter-repo --mailmap` с шагом создания `.mailmap`.
- Проверка атрибуции коммитов больше не требует scope `user:email`: она идёт по эндпоинту
  коммитов, а автор сверяется с логином аккаунта.
- `gh pr merge --auto` не обещает удаление ветки: ветка удаляется отдельной командой после
  состояния `MERGED`.
- Порог размера диффа один — в строках (`git diff --numstat`), а не в символах; baseline-гейты
  сохраняют код возврата (обёртка `log`), пропуск гейта пишется в отчёт строкой, а не молчанием;
  бриф ревьюера получает требования задачи и Stage 1.

### Добавлено

- `scripts/check_examples.py` — гейт переносимости команд: shell-блоки, blockquote-фенсы,
  info-string, префиксы `sudo`/`xargs`/`$`; 23 теста; включён в `make check`, CI и pre-commit.

## 1.1.0 — 2026-11-19

Набор сжат с 27 навыков до 25: два навыка-справочника по `gh` убраны.

### Удалено

- `github-issues`, `github-repo-management`: команды `gh`/`curl` для issues,
  релизов и настроек репозитория — то, что модель знает без навыка. Шаблоны,
  API-рецепты и грабли из их `SKILL.md` (shallow clone в пустой репозиторий,
  приватность не ослабляет лицензию, права в чужой организации, deploy keys
  422) перенесены в `github-pr-workflow/references/` и `templates/`.

### Изменено

- `github-pr-workflow` — один навык на работу с репозиторием GitHub: PR, CI,
  issues, релизы, настройки; `description` и разделы переписаны под это.
- Правила именования веток больше не дублируются: `github-pr-workflow`
  ссылается на `git-naming`, а не держит свой список действий.

### Добавлено

- `make drift` и `scripts/check_drift.py` — сверка репозитория с локальной
  библиотекой навыков: разъехавшиеся, только здесь, только там. Локально, не в CI.
- `make routing-eval` — цель, которую требует Definition of Done (раньше
  команду надо было помнить).
- В routing-кейсы добавлены живые фразы и 8 `known_miss` — честно записанные
  пределы лексического роутинга; кейсов стало 142.

### Исправлено

- CI и документация больше не расходятся по floor ранжирования: 100 в
  `check.yml`, `release.yml`, `Makefile`, `CONTRIBUTING.md` и `AGENTS.md`.
- `check.py` проверяет число навыков в `README.md` и достижимость файлов
  `templates/`, а не только `references/`.
- Укорочены `description`, которые обрезались в индексе хоста:
  `git-worktrees`, `mcp-search`, `skill-library-maintenance`, `using-skills-kit`.
- В README написано, что команды навыков — POSIX shell и как их запускать
  на Windows.

## 1.0.0 — 2026-11-19

Первый публичный релиз.

### Состав

- 27 навыков: `core` — 15, `git` — 8, `code` — 4; плоская раскладка
  `skills/<навык>/SKILL.md`, группа — в `metadata.group` и в `INDEX.md`.
- Пять ролей в `subagents/`, routing-кейсы на все 27 навыков, `CHANGELOG.md`
  и `CONTRIBUTING.md`.

### Установка и проверка

- `scripts/install.sh`: цели `claude`, `opencode`, `codex`, `gemini`, `cursor`,
  `copilot`, `kiro`, произвольный каталог; `--pack` по группам, `--verify`
  проверяет только установленное.
- `make check` — целостность репозитория и язык; `make test` — валидатор,
  установщик, упаковка, поиск и routing-эвалы.
- `scripts/check.py`: контракт frontmatter (`author`, `license`, `platforms`,
  `metadata.group`, `metadata.tags`), ссылки с анкорами, `related_skills`
  только из frontmatter, гигиена по всему репозиторию, обязательные манифесты.
- `scripts/test_packaging.py`: 27 навыков в непосредственных детях `skills/`,
  манифесты указывают на плоский каталог.
- `SKILL.md` ≤250 строк; длинные разборы — в `references/` навыка.

### Релиз

- Версия во всех пяти манифестах; тег `v<версия>`; workflow собирает
  `dist/skills-kit-<версия>.zip`, проверяет совпадение тега и версии и
  публикует ассет.
- `python3 scripts/pack.py --release` — плоская поставка и zip.
