# skills-kit — инструкции агенту

Публичный набор универсальных навыков: работают в любом harness и любом проекте.
Здесь правят навыки и инструкции, а не проектный код.

## Сначала прочитать

- `README.md` — критерии отбора и формат навыка. Главный источник при расхождении.
- `INDEX.md` — каталог: что открывать под задачу.

## Навык: обязательная форма

| Что | Правило |
|---|---|
| Путь | `skills/<навык>/SKILL.md`, плоско: хосты не рекурсируют глубже |
| Группа | `core`, `git`, `code` → `metadata.group` и раздел `INDEX.md`, не каталог |
| Имя | английский kebab, 2–4 слова, класс задачи, без жаргона и сокращений |
| Frontmatter | `name`, `description`, `version`, `author` (`fhfqndj`), `license` (`MIT`), `platforms`, `metadata` (`tags`, `related_skills`) |
| `name` | совпадает с каталогом |
| `description` | триггер в начале, ≤60 символов |
| `INDEX.md` | без строки в нём навыка не существует |

## Содержание

- **Правило — один раз и внутри навыка.** Пересказ в чек-листе или «Граблях» — второе правило; оставляй пункт проверки, не объяснение.
- Навык работает без соседа: ссылка вместо текста запрещена, он устанавливается отдельно.
- Один язык на навык: есть русская проза — весь русский; только английская — остаётся английским.
- Никаких имён инструментов рантайма, личных путей и имён людей. Места владельца — плейсхолдеры: `<workspace>`, `<projects>`, `<kb>`, `<vault>`, `<agent-root>`.
- Длинные разборы — в `references/` навыка, не в `docs/`.

## Перенос из другой библиотеки

- Не копировать как есть: снять рантайм-специфику, личные имена, пути, проектные примеры. Автор — `fhfqndj`.
- `related_skills` — только на навыки этого репозитория: иначе `check.py` падает.

## Перед коммитом

```bash
python3 scripts/check.py
python3 scripts/lang_check.py
python3 scripts/check_examples.py
```

Ноль ошибок. Предупреждение о привязке к рантайму — переписать, не игнорировать.

## Ветка, коммит, PR

- Ветку — до первой правки. Прямой коммит в `master` — нарушение, даже один.
- Правка и коммит разрешения не требуют.
- Коммит — по `skills/git-naming/SKILL.md`: новый навык — `feat`, правка существующего — `fix` или `docs`.
- Мерж в `master` — владелец. Агент открывает PR с описанием и доказательствами и останавливается.
- Как вести PR и CI — `skills/github-pr-workflow/SKILL.md`.

## Релиз

- Тег и GitHub Release — отдельное решение владельца после мержа PR.
- Версию в манифестах поднимает автор правки в обычном PR.
- `release` останавливается, если коммит тега не из PR, влитого в `master`, или не входит в `master`.

## История

Переписывать опубликованное и делать force-push — только по явной просьбе владельца на каждую операцию (`skills/git-naming/SKILL.md`).

## Definition of Done релиза

- `make check` и `make test` зелёные, `routing_eval --min-rank1 100` проходит.
- Упаковочный тест видит 25 навыков в непосредственных детях `skills/`.
- Версия в пяти манифестах совпадает с тегом `v<версия>`.
- `CHANGELOG.md` обновлён, числа `README.md`/`INDEX.md` сверены.
- `python3 scripts/pack.py --release` собирает `dist/skills-kit-<версия>.zip`, и он приложен к релизу.
- Copyright-строки в `README.md` соответствуют адаптациям.

## Не делать

- Не подключать навыки к живой библиотеке и не менять её конфиг без прямой просьбы: меняется разрешение имён у всех совпадающих навыков.
- Не переводить английский навык на русский без решения о переносе: язык — свойство навыка.
